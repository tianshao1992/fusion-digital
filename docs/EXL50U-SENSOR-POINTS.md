# EXL-50U 主机测点叠加与前端管理合同

## 1. 本次实施结论

本次在现有 EXL-50U 浏览器三维样机上叠加 **76 个主机测点 marker**，并提供浏览定位、单点编辑和批量管理能力。测点是独立的数据层，不是第二套装置网格；页面继续只加载当前已发布的 EXL-50U GLB，不加载随源数据提供的 OBJ 或 STL。因此，测点开启、筛选、隐藏或编辑时，装置本体不会重复加载，也不会出现两套三维结构重叠。

项目所有者已确认：这 76 个精确测点可随 EXL-50U 公共可视化在国内站点与 OpenAI Sites 双端正式发布。该授权仅覆盖本合同所述测点数据及其非工程可视化，不扩展为对原始 CAD、OBJ、STL、工程图、装配属性或其他未声明资产的公开授权。

## 2. 数据范围与标识

- 发布记录数固定为 76；每条记录必须有稳定、唯一的发布 ID，不能直接用规范化名称充当主键。
- 源名称中存在 `TF01` / `TF1`、`TF02` / `TF2` 这类规范化后可能冲突的写法；显示名可以保留，内部 ID 必须保持唯一。
- 源三元组的字段顺序和单位定义为 `[H_mm, R_mm, phi_deg]`：
  - `H_mm`：装置高程，单位 mm；
  - `R_mm`：相对装置轴线的主半径，单位 mm；
  - `phi_deg`：环向角，单位 degree。
- 坐标换算采用固定高程基准 `H0 = 4805 mm`。该常量属于当前发布数据合同，不能由界面用户任意改写。

## 3. 坐标基准与 Web 映射

源圆柱坐标先转换为源 CAD 笛卡尔坐标：

```text
x_mm = R_mm * cos(phi_deg)
y_mm = R_mm * sin(phi_deg)
z_mm = H_mm - 4805
```

再按现有 EXL-50U WebGL 的 Y-up 坐标系、以米为单位映射：

```text
[x_web, y_web, z_web]
= [R_mm * cos(phi_deg) / 1000,
   (H_mm - 4805) / 1000,
   -R_mm * sin(phi_deg) / 1000]
```

实现与审核时必须使用角度制输入，并在求三角函数前转换为弧度。所有发布记录应同时保留原始三元组与换算后的 Web 坐标，构建检查需验证二者一致。

上述基准来自当前测点文件与三维模型边界的联合核对，可支撑数字样机中的相对定位；它不等同于经测量部门确认的 as-built 测量坐标系，也不能替代装置坐标基准文件。

## 4. 三维叠加规则

测点层必须满足以下约束：

1. 复用当前 EXL-50U 场景、相机、控制器、装置根节点和坐标变换；不得另建或加载一套 EXL-50U 主机结构。
2. 运行时只从版本化 JSON 生成轻量 marker、标签和选中高亮；不得把 OBJ、STL 或其他源几何复制到 `public/`、构建产物或浏览器网络请求中。
3. marker 只表达名义测点中心。当前不把点自动吸附到网格表面，也不以网格最近点替换原始坐标。
4. 测点拾取应优先于装置部件拾取；选择列表项或点击 marker 都应更新同一个选中状态，并可将相机焦点移动到该点附近。
5. 隐藏、筛选与透明度只影响测点可视层，不得改变装置 GLB、装配树或其他诊断叠加层的数据。

## 5. 三个前端选项卡

主机测点模块采用三个职责清晰的选项卡：

### 5.1 浏览定位

- 按名称、ID 或类别搜索并筛选 76 个测点；
- 显示总数、当前可见数和当前选中项；
- 列表选择与三维 marker 点击双向联动；
- 支持标签显隐、遮挡模式和定位到选中测点。

### 5.2 单点编辑

- 编辑显示名、类别及 `[H_mm, R_mm, phi_deg]`；
- 点击“应用到草稿”后使用本合同的固定映射重算 Web 坐标并更新 marker，避免输入过程中反复重建标记层；
- 校验数值有效性和类别枚举，不允许生成非有限数、重复主键或越过数据合同的字段；
- 可将当前点恢复为公共基线版本。

### 5.3 批量管理

- 批量显示或隐藏筛选结果；
- 展示本地已修改数量并支持全部恢复；
- 将审阅后的草稿导出为 JSON 或 CSV，供数据责任人复核、纳入版本化发布流程；
- 本阶段不在公共页面直接新增、删除或覆盖服务器基线记录。

## 6. 草稿、发布与权威边界

公共版本化 JSON 是页面的只读基线。前端修改仅写入当前浏览器的本地草稿，必须与基线哈希或版本绑定；基线变化时，旧草稿不得被静默套用到新数据上。用户可以恢复草稿或导出草稿，但不能从公共页面直接修改 Git、对象存储、数据库或双端线上资产。

正式更新流程为：导出草稿 → 数据责任人复核坐标与类别 → 更新源数据及版本清单 → 自动校验 → 代码审阅 → 国内站点与 OpenAI Sites 同一版本发布。两端必须使用同一数据文件、相同字节数和 SHA-256，不接受在两个站点分别手工维护测点。

本测点层的权威声明为：

- 可用于公共数字样机中的查找、相对位置理解和界面演示；
- 当前坐标按既定源文件与 `4805 mm` 基准解释，并非 as-built 测量成果；
- 不得用于加工、安装放样、碰撞间隙、结构校核、诊断标定、安全决策或配置控制；
- 若后续获得测量权威坐标，必须以新版本、清晰来源和变更记录替换，不能无痕覆盖。

## 7. 发布门禁

发布检查至少应保证：

1. 数据集恰好包含 76 条记录，稳定 ID、源名称和坐标均完整且唯一；
2. 每条原始三元组均为三个有限数，字段顺序明确为 `[H_mm, R_mm, phi_deg]`；
3. 高程基准严格为 `4805 mm`，Web 映射与本合同公式逐条一致；
4. 数据文件与清单中的记录数、字节数、SHA-256、版本和授权声明一致；
5. 公开包不含源 OBJ、STL 或额外 EXL-50U 三维结构，运行时网络请求也不访问这些资产；
6. 国内站点和 OpenAI Sites 发布同一代码版本与同一测点哈希；
7. 浏览器草稿不能直接写回公共基线，恢复、导出及版本不匹配处理可验证；
8. 界面持续展示非工程权威边界，不把名义测点描述为实装测量结果。

## 8. 验收标准

- EXL-50U 页面可进入“主机测点”，并能使用“浏览定位 / 单点编辑 / 批量管理”三个选项卡；
- 初次进入可见 76 个测点，点位与现有装置共用同一场景且无重复装置网格；
- 列表选择、三维点击、高亮、标签与相机定位行为一致；
- 修改一个三元组并应用后 marker 按固定公式移动，刷新后可恢复同版本的本地草稿；
- 单点恢复、全部恢复、批量显隐和导出均有效，且不会改变公共静态 JSON；
- 构建产物中不存在本次源 OBJ/STL，自动检查和生产构建通过；
- 双端抽查的数据版本、记录数与哈希完全一致。
